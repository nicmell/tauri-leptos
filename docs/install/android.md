# Android

## Prerequisites

- Android Studio (or command-line SDK) with SDK, NDK, and JDK 17+
- Environment: `ANDROID_HOME` and `NDK_HOME` pointing at the SDK/NDK
- Rust targets:

```bash
rustup target add aarch64-linux-android armv7-linux-androideabi \
  i686-linux-android x86_64-linux-android
```

## How the app runs on Android

The Tauri lib starts the same axum SSR server in-process (the `ssr`
code path is always on for Android) and points the webview at
`http://127.0.0.1:3000`.

Two Android-specific mechanisms:

- **`site.tar` extraction.** APK assets are not filesystem files and
  asset directories cannot be enumerated, so the frontend ships as one
  tar resource (`scripts/pack-site.sh`, wired via
  `tauri.android.conf.json`) and is unpacked into
  `app_local_data_dir()/site` on first launch, re-extracted when the app
  version changes.
- **Cleartext to loopback.** `res/xml/network_security_config.xml`
  allows plain http to `127.0.0.1`/`localhost` only (and, unlike the
  `usesCleartextTraffic` gradle placeholder, also applies to release
  builds).

## Project generation

`src-tauri/gen/android/` is generated by `cargo tauri android init` and
**committed**, because it carries the network-security-config file and
its manifest reference. Re-running `android init` can overwrite those
edits — review the git diff afterwards.

## Develop / build

```bash
cargo tauri android dev                          # emulator or device
cargo tauri android build --debug --target aarch64
cargo tauri android build                        # release (needs signing)
```

Logs (including the extraction and server startup):

```bash
adb logcat -s tauri-leptos
```

For release signing, follow <https://v2.tauri.app/distribute/sign/android/>.
